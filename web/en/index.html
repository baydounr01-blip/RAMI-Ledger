THE IDEA

Bitcoin discards the losing branches. RAMI-Chain keeps them.

In a normal chain only the chain with the most work survives; orphan blocks are thrown away. Here the entire tree persists: the "sibling branches" (same parent, different reality) coexist and are auditable forever. The fork-choice — the "decoherence" — picks the observer's branch deterministically.

P2 · CAUSALITY

Link = cause

Each block references the hash of the previous one over fixed big-endian bytes; the consensus hash does not depend on floats or on JSON. Anyone can reproduce it.

P3 · BRANCHING

Sibling branches

Two blocks with the same parent are different realities. Both are kept; none is discarded. The same balance can exist in two branches — never within one.

P4 · DECOHERENCE

Fork-choice

The observed branch = most accumulated work. If two branches tie EXACTLY, they collapse to one by a deterministic tiebreaker (see "unproven mathematics").

TECHNOLOGY

What's inside

All in Rust, with a minimal set of dependencies and verifiable from the bytes. Two experimental pieces are clearly labeled and cannot break consensus even if they fail.

CONSENSUS

PoW + computed difficulty

SHA-256d, Bitcoin-style compact target and per-block LWMA retarget. Calibrated genesis: ~1 CPU at 1e6 H/s ⇒ 60 s/block, difficulty 60,000,000, nBits 0x1d479531.

LEDGER

Native commit-reveal

Publish sha256(signal‖nonce) BEFORE the fact and reveal it afterward, as a first-class transaction. Anti-look-ahead rule: the reveal goes in a strictly later block.

NEURAL NETWORK

Branch invariance (UBR)

A whole bit-exact MLP scores how much a branch "survives" small perturbations. It is advisory only: it never decides validity, PoW or fork-choice.

UNPROVEN MATHEMATICS

Coherence collapse

The tiebreaker for branches of identical work uses the Collatz conjecture. Bounded by a step cap: if the conjecture were false, it degrades to lexicographic order. It never affects issuance or validity.

ACCOUNTS

Issuance and anti-double-spend

Account model with sequential nonce (double spend impossible), issuance with halving and a ~21 M cap, and testnet staking. Integer arithmetic, no floats in consensus.

VERIFIABLE

Parity and tests

Canonicalization, hashing and commit-reveal match byte for byte with the Python reference. The core carries dozens of tests; rami-node verify revalidates the entire chain.

HOW UPDATES WORK · like Bitcoin Core, but one click

From the app (the normal way): when a new version is out, the dashboard tells you; press "Update now". The app downloads the official installer, verifies its SHA-256 against the published one, installs the new version over the current one, quits and relaunches itself. Your wallet and chain are untouched.
By hand (if you prefer): download the new file above and open it. macOS: double-click RAMI-Chain inside the .dmg → "Install" (replaces the previous version and closes the running one). Windows: run the installer (closes the open wallet and replaces it). Linux: replace the .AppImage. If you open a new version while the old one is still running, the new one asks it to quit and takes its place.
If something looks off: ~/.rami/gui-launch.log records every step (starting version, download, verification, install); the Update tab shows where the app is running from.

Advanced users only · verify, open and install from the terminal
1 · ALWAYS verify before opening. Check that your download's SHA-256 matches SHA256SUMS.txt: shasum -a 256 file (macOS/Linux) or certutil -hashfile file SHA256 (Windows). If it doesn't match, delete it.

GET STARTED

Run the wallet, or build it

THE EASIEST WAY

Desktop wallet in one step

# unzip the release and run:
./rami-gui --network testnet
# open the dashboard at http://127.0.0.1:8645 — mine, send,
# receive, stake and predict, all from there.
# connect to a known peer:
./rami-gui --network testnet --connect PEER_IP:30301

Prefer the terminal? The P2P node and the wallet CLI:

1 · Build

# requires stable Rust (rustup.rs)
git clone https://github.com/baydounr01-blip/rami-ledger
cd rami-ledger/chain
cargo build --release
# binaries in target/release/: rami-node, rami-wallet

2 · Create wallet

rami-wallet new --label yo
# prints your address (pubkey in hex)
rami-wallet address --label yo

3 · Genesis and mining (local network)

ADDR=$(rami-wallet address --label yo)
rami-node init --chain ./midato --network regtest --miner $ADDR
rami-node mine --chain ./midato --network regtest \
          --address $ADDR --blocks 5
rami-node status --chain ./midato --network regtest

4 · Send and verify

rami-wallet send --chain ./midato --network regtest \
   --to <OTHER_PUBKEY> --amount 10 --label yo
rami-node mine --chain ./midato --network regtest --address $ADDR
rami-node verify --chain ./midato --network regtest

regtest mines instantly (difficulty 1), ideal for testing. To join the P2P network: rami-node run --network testnet --connect IP:30301 --miner $ADDR --mine (listens, syncs and mines). rami-wallet commit / reveal anchors predictions on the chain.

HOW YOU GET COINS

Free: by mining or staking

Nobody sells you RAMI-Chain coins. They are obtained at no cost. With the desktop wallet, the main way is mining with one click: the block reward goes to your account. You can also stake. There is no purchase or payment: any website or person that asks you for BTC, euros or other crypto in exchange for RAMI-Chain coins is a fraud and is not ours.
Mine: press "Start mining" in the wallet
Staking: stake your RAMI from the dashboard
No KYC, no purchase, no payment.
No premine · finite issuance (~21 M)

Since v0.3 the faucet software ships with the node (rami-node faucet): any operator can hand out coins from their own funded node, with a drip and a per-address cooldown — and it never asks for payment. Even so, the recommended way is still mining from the wallet: it is instant and depends on nobody. No single point of failure: the network is P2P, it does not depend on any server.
